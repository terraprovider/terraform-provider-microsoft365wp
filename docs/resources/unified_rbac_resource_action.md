# microsoft365wp_unified_rbac_resource_action (Resource)

Represents an operation that an authorized principal is allowed to perform. <br/> Also see [Microsoft docs for unifiedRbacResourceAction](https://learn.microsoft.com/en-us/graph/api/resources/unifiedrbacresourceaction?view=graph-rest-beta).

_Provider_ Note: Use this resource for Entra **protected actions**: it assigns a Conditional Access authentication context (`authentication_context_id`, e.g. `c1`, which can be managed with the resource `microsoft365wp_authentication_context_class_reference`) to a resource action of the `microsoft.directory` namespace, e.g. `id = "microsoft.directory-conditionalAccessPolicies-create-post"`. Only actions with `is_authentication_context_settable = true` support this (use the plural data source with `odata_filter = "isAuthenticationContextSettable eq true"` to list them). If `authentication_context_id` is not set, the provider removes any authentication context from the action.
Resource actions cannot be created or deleted. Therefore this resource always updates an existing action (determined by `id`), and on destroy it only removes the authentication context.
MS Graph sometimes acknowledges a change of the authentication context without applying it, especially if several actions are changed at the same time (only one of them takes effect). The provider therefore changes one action at a time (even with Terraform's parallelism) and reads it after each change until MS Graph returns the new value, writing it again if needed. This takes about 20 s per changed action (e.g. about 8 min for the first apply of all 24 actions that support an authentication context).
Note: once an action like `conditionalAccessPolicies` create/update/delete is protected, app-only clients need the provider option `enable_claims_challenge` to keep managing the protected objects.
