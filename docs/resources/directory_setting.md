# microsoft365wp_directory_setting (Resource)

Directory settings define the configurations that can be used to customize the tenant-wide and object-specific restrictions and allowed behavior. For examples, you can block word lists for group display names or define whether guests are allowed to be group owners.

By default, all entities inherit the preset defaults. To change the default settings, you must create a new settings object using the [directorySettingTemplates](directorysettingtemplate.md). When the same setting is defined at both the tenant-wide and to a specific group, the entity-level setting overrides the tenant-wide setting. For example, the tenant-wide setting might allow existing members of groups to invite guests; but an individual group setting can override and not allow the operation.

Group-specific settings apply to only Microsoft 365 groups.

Also see [Microsoft docs for directorySetting](https://learn.microsoft.com/en-us/graph/api/resources/directorysetting?view=graph-rest-beta).

_Provider_ Note: Manages a tenant-wide directory setting, i.e. the values of one directory setting template (e.g. `Group.Unified` for Microsoft 365 groups or `Password Rule Settings` for Entra password protection). Only one setting can exist per template in a tenant.<br><br> If a setting for the template already exists in the tenant (as is often the case for `Group.Unified`), it must be imported first. The template id can be used as the import id, so the same import block works for every tenant, e.g. `import { to = microsoft365wp_directory_setting.group_unified, id = "62375ab9-6b52-47ed-826b-58e47e0e304b" }`. To import only if the setting exists, use `for_each` on the import block with the template ids returned by the data source `microsoft365wp_directory_settings`. After an import, all values of the template are in state, so the first plan shows the values that are not configured being removed (from state only, MS Graph keeps them).<br><br> Destroying this resource deletes the setting in MS Graph, which resets all of its values to Microsoft's defaults, including values that are not managed by this resource. Set `destroy_resets_managed_values_only` to reset only the managed values instead. To stop managing a setting without changing it at all, use a `removed` block with `lifecycle { destroy = false }`.<br><br> Template-specific validation (e.g. of naming policies or group ids) is performed by MS Graph on apply. Managing `Password Rule Settings` additionally requires the Entra role Authentication Policy Administrator.

## Example Usage

```terraform
terraform {
  required_providers {
    microsoft365wp = {
      source = "terraprovider/microsoft365wp"
    }
  }
}

/*
.env
export ARM_TENANT_ID='...'
export ARM_CLIENT_ID='...'
export ARM_CLIENT_SECRET='...'
*/


locals {
  directory_settings = {
    group_unified = {
      template_id = "62375ab9-6b52-47ed-826b-58e47e0e304b" # Group.Unified
      values = {
        EnableGroupCreation       = "true"
        AllowGuestsToAccessGroups = "true"
        UsageGuidelinesUrl        = "https://contoso.example/groups"
      }
    }
    password_rule_settings = {
      template_id = "5cf42378-d67d-4f36-ba46-e8b86229381d" # Password Rule Settings
      values = {
        LockoutThreshold         = "10"
        LockoutDurationInSeconds = "60"
      }
    }
  }
}

# Settings that already exist in the tenant must be imported first (by template id). This imports only those that
# exist, all others will be created.
data "microsoft365wp_directory_settings" "all" {
}

import {
  for_each = {
    for k, v in local.directory_settings : k => v.template_id
    if contains([for s in data.microsoft365wp_directory_settings.all.directory_settings : s.template_id], v.template_id)
  }
  to = microsoft365wp_directory_setting.this[each.key]
  id = each.value
}

resource "microsoft365wp_directory_setting" "this" {
  for_each    = local.directory_settings
  template_id = each.value.template_id
  values      = each.value.values
}
```

## Schema

### Required

- `template_id` (String) The id of the directory setting template this setting is based on (e.g. `62375ab9-6b52-47ed-826b-58e47e0e304b` for `Group.Unified`). Changing it creates a new setting.
- `values` (Map of String) The settings to apply, as a map of setting name to value (all values are strings, e.g. `"true"`). The names and allowed values depend on the template (see `directorySettingTemplates` in MS Graph or the MS Learn link below). Only the names listed here are managed by this resource: MS Graph fills all other values of the template with their default values on creation, and keeps their current values on updates. Removing a name from this map therefore does not reset its value in MS Graph, it only stops managing it. Values are compared as sent (case-sensitive). / https://learn.microsoft.com/en-us/graph/api/resources/directorysetting?view=graph-rest-beta

### Optional

- `destroy_resets_managed_values_only` (Boolean) The _provider_ default value is `false`.  
_Provider_ Note: Controls what happens when this resource is destroyed (including replacements caused by changing `template_id`). If `false` (the default), the setting is deleted in MS Graph, which resets all of its values to Microsoft's defaults. If `true`, only the values listed in `values` are reset to the defaults of the template and the setting itself is kept, so values maintained outside of Terraform (e.g. in the Entra admin center) are left untouched; to manage the setting with Terraform again later, it must be imported. This attribute is not sent to MS Graph and is taken from state on destroy, so a change to it must be applied before the resource is destroyed.

### Read-Only

- `display_name` (String) Display name of this group of settings, which comes from the associated template. Read-only.
- `id` (String) Unique identifier for these settings. Read-only.

## Import

Import is supported using an `import` block (or the `terraform import` command) with the value of `id`:

```terraform
import {
  to = microsoft365wp_directory_setting.example
  id = "<id>"
}
```

Instead of the `id`, the `template_id` can be used as the import id (preferred, as it is the same in every tenant), e.g. `id = "62375ab9-6b52-47ed-826b-58e47e0e304b"` for `Group.Unified`.
